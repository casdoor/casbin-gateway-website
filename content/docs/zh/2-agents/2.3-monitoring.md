三份不同的记录，来自三个不同的源头：

| 页面 | 来源 | 需要 |
| --- | --- | --- |
| **会话** | Agent本来就会写在磁盘上的会话记录 | 什么都不需要 |
| **活动记录** | Gateway装进Agent里的监控钩子 | 该Agent开启监控 |
| **外发监测**，在Agent自己的页面上 | Agent自己的进程建立的网络连接 | Windows |

它们都不等于[LLM记录](../4-governance/4.2-llm-records.md)——那一页是Gateway自己转发出去的东西。

## 会话

这些Agent的每一次会话，读自它们自己的会话记录：整段对话，一条一条，带每一轮用掉的token。

页面会统计一共有多少次会话、今天跑了多少、其中多少来自会话记录而不是监控，并且可以筛到某一个Agent或某一个来源。

因为会话记录不管Gateway在不在路径上都会写，所以这一页覆盖那些完全没走Gateway的会话——包括用自己订阅的Agent。

## 监控

监控按Agent开启，在它的卡片上或它自己的页面上。Gateway会在那个Agent自己的配置里装一个钩子，此后记录它做了什么：提示词、工具调用，以及它弹给你的权限询问。

这是**只读审计**。Agent做任何事都不会等Gateway，开了监控也不会改变任何回答。

不是每个Agent都支持——[README](https://github.com/apache/casbin-gateway/blob/master/README_zh.md#每个-agent-支持到什么程度)那张表的**监控**列是当前清单。

关掉监控会把钩子从该Agent的配置里去掉。`casbin-gateway uninstall`会对所有Agent一次性做同样的事（[5.5](../5-operations/5.5-lifecycle.md)）。

## 活动记录

**活动记录**是被监控的Agent此刻正在做什么：每一次工具调用、调用的对象、耗时多久。

Agent正在跑的时候就该开着这一页——一次长时间的自动执行，在这里读起来是一份"它到底动了什么"的清单，而不是终端里刷屏的输出。

## 外发监测

代理只能看到Agent发给模型的请求。Agent完全可以把数据发到别处：直接传到云存储的整个代码仓库，不会经过任何代理。每个Agent自己页面上的**外发监测**，就是用来看这些的。

Gateway从启动那一刻起，就监测每个Agent自己的进程建立的网络连接，不需要先开启监控。监测连接目前**只支持Windows**。在其他系统上，这一节只会在出现[整个工作区被打包上传](#整个工作区被打包上传)时显示，那部分是从磁盘上读出来的。

### 记录什么

满足下面任一条件的上传，会被记为**可疑外发**：

| 发现 | 条件 |
| --- | --- |
| **对象存储** | 任何一次连到对象存储上传地址的连接：阿里云OSS、Amazon S3、腾讯云COS、火山引擎TOS、华为云OBS、Google Cloud Storage、Azure Blob、Cloudflare R2等。客户端往这些地方传，通常是在用厂商签好的凭据上传文件 |
| **大量上传** | 一分钟内向同一个目的地发送5MB以上，且目的地不是模型API——Agent本来就该把上下文发给模型API |

一次发现要等它的目的地安静一分钟后才写入，所以一次上传无论用了多少个连接，都只记一行。每条发现也会出现在**活动记录**里，这个Agent在**Agent客户端**页的卡片上，名字旁边会多一个红点。

### 连过哪些地址

**连接过的地址**展开后，是Gateway开始监测以来这个Agent的进程连过的每一个地方：主机名、类型、连接次数，以及发送和接收的字节数。

| 类型 | 是什么 |
| --- | --- |
| **模型API** | 模型厂商的API |
| **对象存储** | 对象存储的上传地址 |
| **遥测** | 错误上报和统计分析服务 |
| **本机进程** | 这台机器上的另一个进程，通常是代理，它会把数据接下来去了哪里藏起来——页面会写出是哪个进程 |
| **其他** | 其他所有地址 |

主机名读自系统的DNS缓存，所以一个存储桶显示的是Agent请求的那个名字，而不是它背后CDN节点的地址。

### 统计流量需要管理员权限

Windows只对以管理员身份运行的进程按连接统计字节数。没有管理员权限时，这一节会显示**未统计流量**：目的地和对象存储连接照常监测，但大小显示为`-`，也就识别不出大量上传。

### 整个工作区被打包上传

有些Agent会在上传前把整个工作区打包。ZCode 3.12.x及更早的版本，会在每次提问前把工作目录连同`.git`一起打包，传到阿里云OSS。打包留在磁盘上的痕迹比上传本身存在得更久，所以即使上传发生时Gateway没在运行，Gateway也能读回来，并显示是哪个工作区、多大、其中多少文件来自`.git`，以及失败过几次。

这个包里有完整的提交历史。**历史中出现过的密钥都要轮换**，已经删掉的也一样。

## 钩子同时也是一个执行点

不把模型流量走Gateway的Agent，**工具**开关仍然对它生效：Gateway装的那个钩子会在工具真正执行前先问Gateway一次，开关不允许的调用会被拒掉。

模型和供应商这两类规则不一样：它们只能约束走代理的请求。权限页会说明某个Agent属于哪种情况（[4.1](../4-governance/4.1-permissions.md)）。
